# Store assets and listing package

The store listing is part of the release. Capture the shipping build, use synthetic or consented
data, and make every claim match the app. Exact upload slots change; validate the live Console or
Connect requirements on the day of submission.

## Shared asset process

1. Create a master icon from owned artwork. Export platform-specific package icons; do not reuse a
   low-resolution store icon as a launcher icon.
2. Make a screenshot plan by store, device class, orientation, locale, and feature. Show the core
   workflow, not only a splash, login, title, or marketing screen.
3. Capture screenshots from the release build with final copy, permissions, pricing, and empty or
   error states as relevant. Use fictional accounts and remove confidential data.
4. Localize screenshots, preview video overlays, captions, descriptions, and accessibility text
   when they contain language. Keep an asset manifest with source build and checksum.
5. Upload early to find live slot, file, and crop errors. Re-upload only the final reviewed assets.

## Platform notes

### Apple

Provide the current App Store Connect app icon and each required screenshot family. Apple review
requires screenshots to show the app in use. Metadata and screenshots must accurately represent
the core experience. Do not use competitor branding, unsupported claims, actual customer data, or
material that lacks rights clearance.

### Google Play

Provide the Play listing icon. Current preview-asset guidance requires a 1024 x 500 JPEG or 24-bit
PNG feature graphic without alpha when a feature graphic is used. Play supports up to eight
screenshots per device type; large-screen listings can require four screenshots and exact
dimensions/orientation rules. Check the live listing controls and target device types.

### Microsoft Store

At least one screenshot and a description are required for a Store listing. Provide at least four
per supported device type when possible. Desktop screenshots must be PNG, at least 1366 x 768,
and no larger than 50 MB. Keep critical material out of the lower quarter, where Store overlays
can appear. Package icons need the required Windows scale variants.
